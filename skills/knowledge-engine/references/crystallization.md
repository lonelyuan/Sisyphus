# 结晶化：一张卡是一颗知识结晶，不是一次对话

这版最要治的病：**每次对话结一张卡**。用户原话——"英语雅思话题，明显放在一个 md 中就够了，还是每次对话都新建一个"。结果是一堆语义相邻的碎卡（雅思选择 / 雅思分数 / 雅思结构…），查重查不出来（它们确实是不同问题），于是各自成文。要输出的是**知识的结晶**，不是对话的沉渣。

## 一句话心智

> **卡 = 一颗"结晶主题"：一个未来的你会当作"一件事"去查、并会反复回来的条目。对话是溶液，结晶在溶液里长大、变致密——同一主题多轮对话应让同一颗结晶更大更有序，而不是析出一堆碎晶。**

所以**卡的粒度 = 检索与复用的粒度，不是聊天轮次的粒度**。判断单位永远问"这是**哪颗结晶**的知识"，而不是"这次对话产出了什么概念"。

## 一颗结晶长什么样（anatomy）

一颗成熟结晶 = **一句话定义 + 若干 H2 小节 + 待确认**，体量约等于一篇好博客的"一节"到"一篇"。它靠**小节增生**长大：

```markdown
> [!info] 一句话定义
> <一眼想起这颗结晶是什么>

## <小节 A>        ← 第一次对话沉淀
## <小节 B>        ← 第二次对话补进来（不是新开一张卡）
## <小节 C>        ← 第三次对话再补/精化
## 待确认
- [ ] …
```

**每一轮新对话，动作是"给这颗结晶加/精一个小节"，绝不是"追加一段对话流水账"，更不是"另开一张邻居卡"。**

## 原子性双筛：它配单独一张卡，还是只是某颗结晶的一节？

一块知识**只有同时过下面两关**，才配自己一张卡；否则它是**某颗已有/应有结晶的 H2 小节**。

1. **独立可检索**：未来的你会**直接按它的名字**去查它吗？还是只会经由它的母主题查到？
   - "参数化查询" → 会（防御手段，独立查）。
   - "雅思分数水平对照" → 不会（你会查"雅思"，分数只是其中一节）。
2. **多处可复用 或 会撑爆母卡**：它是**≥2 个主题都会 `[[链接]]` 指向**的枢纽概念吗？或者它已长大到塞进母卡会让母卡失衡？
   - "参数化查询" → 是（SQL 注入、ORM 安全、其它注入都指它）。
   - "雅思分数水平对照" → 否（只有"雅思"用它）。

**任一关不过 → 它是小节，不是卡。** 这条同时解释了两端：把雅思三碎卡并成一颗，也保住"参数化查询"这种真正被多处引用的原子卡——**原子，但不琐碎**。

> 反过来说：不要因为"想拆得细一点更 Zettelkasten"就把只服务于单一母主题的一节切成独立卡。切分的正当理由只有"独立可检索 + 多处复用/母卡过大"，不是洁癖。

## 决策树：归并 / 新建 / 拆分（建卡前必走）

```
1. 先命名这块知识的【耐久主题】——按"未来会查什么"命名（"雅思"而非"雅思分数"）。
2. search_knowledge / list_knowledge：这个主题已有结晶了吗（哪怕标题略不同）？
   ├─ 有 → 【归并】：读回那颗卡 → 加/精一个小节（theory 补充式，写超集）→ 写回。完事。
   └─ 无 → 过【原子性双筛】：
        ├─ 双筛都过 → 【新建】一颗结晶。
        └─ 有一关不过 → 找它其实是"哪颗结晶的一节"：
             ├─ 那颗结晶已存在 → 【归并】进去（同上）。
             └─ 还不存在 → 【新建那颗母结晶】，把这块知识作为它的第一个小节播下去
                （别为这一节单独建一张碎卡）。
3. 【拆分】（维护动作，少用）：某颗结晶的一节长大且变得【独立可检索+多处复用】——
   即出现真正的"概念缝"——才把它抽成独立卡，母卡留一行摘要 + [[link]]。
   永远沿【概念缝】拆，绝不沿【对话缝】拆。
```

**默认动作是【归并】，不是【新建】。** 新建是例外，要过双筛才配。

## 反模式画廊

| 反模式 | 症状 | 正解 |
|---|---|---|
| **对话即卡** | 同一主题每问一次就新开一张 md | 认耐久主题 → 归并进同一颗结晶的新小节 |
| **碎晶** | 一堆 3–5 行、只服务单一母题、彼此强链的小卡 | 双筛淘汰 → 并成一颗，`delete_note` 清冗余 |
| **流水账** | 卡里按时间追加"今天又聊到…" | 归位到对应 H2 小节，重组而非堆叠 |
| **洁癖过拆** | 把只被母题用的一节切成独立卡求"原子" | 双筛第 2 关拦下：不复用就是小节 |

### 雅思：before → after（本次真实整改）

**before**（3 张碎卡，都在 `kb/personal`，全过不了双筛第 1 关——你只会查"雅思"）：
- `英语考试选择：托福还是雅思`
- `雅思分数水平对照`
- `雅思考试结构与备考路径`

**after**（1 颗结晶 `雅思备考`，小节增生）：
```markdown
# 雅思备考
> [!info] 一句话定义
> 雅思(IELTS)：听说读写四科、0–9 分；分 Academic / General Training / UKVI…

## 选 IELTS 还是 TOEFL      ← 原「英语考试选择」
## 考试结构与类型            ← 原「结构与备考路径」的结构部分
## 费用                      ← 同上
## 分数水平对照              ← 原「分数水平对照」
## 备考路径                  ← 合并
## 待确认
```
三碎卡 → 一颗可当"雅思备考"整篇博客读的结晶。指向旧标题的 `[[wikilink]]` 改写到 `[[雅思备考]]`，旧卡 `delete_note` 清掉。

## 去碎片化（defragment）例程

属于 [taxonomy.md](taxonomy.md) 平衡维护的一种，触发：用户说"整理/精炼知识库、感觉琐碎、结晶化"，或 rebalance 时顺手做。

1. `list_knowledge` 全量 → 按**主题聚类**扫描标题，找**主题相同/相邻但拆成了多张**的簇（尤其某领域里名字共享前缀的：`雅思*`、`XX 注入*`）。
2. 对每个簇跑原子性双筛：**过不了的合成一颗结晶**（挑最恰当的耐久主题名当 title）。
3. 执行：`write_knowledge_note` 写合并后的超集卡（小节化组织）→ 把指向旧卡的 `[[wikilink]]`（含 `index.md`）改写到新标题 → `delete_note(旧标题)` 逐张清冗余。
4. 更新该领域 `index.md` 的卡片列表；回报一行：`🔮 结晶化：personal 雅思(3→1《雅思备考》)…`。

> `delete_note` 只删被指定的那张卡、软删索引、留 `knowledge_pruned` 溯源；**不会自动改别处的 wikilink**——先改链再删卡，别留断链。
