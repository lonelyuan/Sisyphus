# 四大场景 · 功能路由

知识进入 `kb/` 的四种工作模式。**先判定场景**（见下路由），再走对应协议。四者写进同一个 vault、互相 `[[link]]`，共用 [taxonomy.md](taxonomy.md) 的分类两轴、[types.md](types.md) 的类型与可靠性、[crystallization.md](crystallization.md) 的结晶化归并。

## 路由：这轮属于哪个场景？

```
用户给了压缩包 / 文件夹 / 网址，说"整理/消化这批"        → ② 批量学习
用户给本人维护的 KM/文档，说"这是我的主空间/原文"        → ① 第一方成品链接（不复制、不再精炼）
用户"我想系统学 X / 帮我深挖 X"，需要外部检索             → ③ 主动探索
结论"得跑一遍才算数"(payload/exploit/PoC/CTF 复现)      → ④ 实践验证
其它日常问答 / 学习 / "记一下"（默认）                    → ① 日常对话
```

**串联**：③ 探索抓到的资料 → 走 ① 的后反思沉淀；②/③ 产出的技术结论 → 可交 ④ 验证；④ 的复现结果 → 回写 ①/② 卡片的可靠性（升 `已复现`）。**四个场景落库共用同一套规则**：默认归并非新建、别照搬别人的结构、分类归位、标可靠性。

---

## ① 日常对话（灵感 / 轻量补充）—— 日常主力 ✅

答完用户问题 / 处理完材料之后按 `knowledge_reflection` 模式收尾。`strong` 自主写入，`weak` 只读判断并征求选择，`off` 不执行。触发：查术语、学习、消化会议或文档、随口一问、用户说"记一下/沉淀"。纯闲聊 / 纯操作不触发。

**核心是"慎重"**：先判本轮**该不该动库**（四判定），大多数轮次答完即止、不留痕：

| 判定 | 情形 | 动作 |
|---|---|---|
| **不值得** | 一次性、太宽泛、纯操作、闲聊 | 不动库 |
| **重复** | 已有结晶已覆盖且够好 | 不动库（最多补一条来源/例子） |
| **扩充已有** | 有对应结晶但薄 / 缺一个侧面 | 归并：长一个 H2 小节（**默认路径**） |
| **全新话题** | 无对应结晶、且过原子性双筛 | 新建一颗结晶 |

遇到**用户本人维护的成熟文档**时，先判定为第一方成品：只把原链接接入相关 MOC/已有节点；文档已经承担内容维护职责时，不再抽卡、不 `save_source`。只有用户明确要求拆解其内容，才按结晶规则加工，而且仍优先更新既有节点。

完整六步见 [SKILL.md 模式①主循环](../SKILL.md)。三道筛（抽候选时）：① 三个月内还会再遇到吗？② 是站得住的概念/工具/方法，不是宽泛词？③ 值得单独一张卡、还是某颗结晶的一节？**一轮 0 个也正常，别为了记而记。**

常驻触发：靠全局或项目 `AGENTS.md` 的 `knowledge_reflection: weak|strong|off` 选择强度；更具体的项目规则覆盖全局规则。

## ② 批量学习（吸收一个现有知识库）✅ 本地夹 / 🟡 在线整站

有一堆已攒下的资料——压缩包、收藏夹导出、报告集、旧笔记、或一个在线知识站——要尽可能**完整梳理**后**融入自己的体系**。

```bash
cd services/knowledge-agent
SISYPHUS_VAULT=/Users/chenzhongyuan/Obsidian/mihoyosec node index.mjs --batch /path/to/文档文件夹
```

**铁律：融入，不照搬。** 这是本场景的灵魂——

1. **遍历 / 抓取**：逐篇过；仅对重要的**外部材料**且确需逐字溯源时 `save_source(folder=…)`——
   原文就地放进它讲的那个话题的文件夹。用户自己的持续维护文档（公司 KM 等）**只保留链接**，
   不镜像、不二次精炼；目录/索引类快照一律不存。压缩包先解压成文件夹；在线站见下方 gap。
2. **去芜存菁**：抽取每篇**值得沉淀**的概念，丢掉水分、营销、重复。不是每篇都要建卡。
3. **按我的分类学归位**：概念进**我自己的话题树 + 结晶格式 + 可靠性标签**，**绝不复制对方的目录结构或原文段落**。查重：与已有结晶**归并**（长小节），无则新建。
4. **结构反哺（关键）**：如果对方的**抽象/分类比我更好**（更稳的父概念、更清的边界），**提议优化我自己的树**（MOVE/SPLIT/新领域，走 [taxonomy.md](taxonomy.md) rebalance，人工确认后执行）——学的是**组织方式**，不只是内容。
5. **收尾**：`kb_doctor` 体检 → `refresh_mocs` 刷新受影响领域枢纽 → 报告（处理多少篇、归档多少原文、新建/更新/合并多少卡、结构调整建议）。

先小批量试跑、人工抽查质量，再放大。

> 🟡 **Gap（在线整站）**：`--batch` 目前吃**本地文件夹**。在线知识站要么先抓取落地（`wget`/导出为文件夹再喂），要么在对话里用 web 工具逐页抓 → `save_source` → 走 ① 沉淀。**整站自动爬取器未做**（未来接 [knownengine-design.md](knownengine-design.md) §5.1 Capture Layer）。

## ③ 主动探索（搜索引擎深研）🟡 可用，搜索 API 未优化

用户想系统学一个方向、或补知识库里**薄弱 / 标 `#待确认`** 的缺口时，主动上网深研、尽量丰富地检索。

```bash
cd services/knowledge-agent
SISYPHUS_VAULT=/Users/chenzhongyuan/Obsidian/mihoyosec node index.mjs "LLM 越狱攻防"
```

Codex 深研线程：有联网/deep-research 工具就用 → 多角度检索、尽量覆盖 → 只把需要逐字溯源的重要外部原文 `save_source(folder=…)` 就地归档进对应话题夹 → 重点补 `#待确认` 缺口与缺失核心概念 → 产出分类归位的 kb 结晶卡（默认归并）→ 报告新建/更新/归档与各领域卡数。

也可在对话里直接用内置 `deep-research` skill 做研究，然后走 ① 的后反思把结论沉淀。

> 🟡 **Gap（搜索优化）**：目前依赖 Codex / 内置工具的通用联网能力，**没有专门的多引擎/学术库（arXiv、CVE/NVD、GitHub、CTF-Wiki）检索优化与去重排序**。够用但不"尽可能丰富"。未来接专用检索适配器（参考 [knownengine-design.md](knownengine-design.md) §10.1 数据来源、§14.1 混合检索）。

## ④ 实践验证（沙箱执行验真）🔴 验证器未建，暂人工

有些结论**跑一遍才算数**：payload 是否真能注入、exploit 是否真能 RCE、PoC 是否可复现、CTF 题能否拿到 flag。目标是在**隔离沙箱**里实际执行，把卡片可靠性从 `待确认/多源印证` 升到 **`已复现`**，并留下产物（命令日志/flag/截图）。

**目标流程**（映射 [knownengine-design.md](knownengine-design.md) §10.3）：判断可复现（有 Dockerfile/源码/附件/靶场）→ 生成验证计划 → **隔离环境**构建运行 → 保存产物按 hash 归档 → 更新卡片：可靠性升 `已复现` + 记录证据来源。

**安全边界（务必守，见 [knownengine-design.md](knownengine-design.md) §20）**：默认**无外网**、一次性销毁环境、限 CPU/内存/时长、**不在宿主机直接跑未知代码/样本**、PoC 仓库默认只读、destructive 命令不自动执行。

> 🔴 **现状：沙箱验证 agent/工具尚未实现。** 当前可行的临时路径：
> 1. 你（或用户）**手动**在自己的隔离环境（Docker/一次性 VM）里跑通，把命令、结果、flag 作为证据 → 手动 `write_knowledge_note` 把该卡可靠性标 `已复现`、在 `sources` 记录复现环境/命令。
> 2. 需要落地时，新建一个 verification runner（planner + sandbox + artifact 存储），参考 [knownengine-design.md](knownengine-design.md) §5.5 / §10 / §15。这是知识工程拓展到 CTF 的核心增量工作。
> **在工具就位前，agent 不得把未真正跑通的结论标成 `已复现`。**

## 四场景的共性

- 都遵守三个隔离（原始材料靠 `type: source` + 单向连接 + `publish: false` 隔离，**就地存放**；第一方成品只链接不复制；`state` 不与 `best-practice` 混）与分类两轴。
- 都以 `list_knowledge` / `search_knowledge` 按**主题**查重打底，默认**归并**入已有结晶而非另开碎卡（[crystallization.md](crystallization.md)）。
- 都先定位母结晶/MOC 和真实邻居，再决定是否需要页面；标题只用短主题名，不用长标题代替组织关系。
- 都不照搬来源结构，而是重蒸馏进自己的话题树 + 结晶格式 + 可靠性标签。
- 产出后都应让分类更均衡（[taxonomy.md](taxonomy.md)）。
- 现状标注（✅ 已实现 / 🟡 半实现有 gap / 🔴 未建）如上，**agent 遇到 gap 要如实说明并给临时路径，不假装能力**。
